# Diagrams

The diagram at the top of the README is drawn with the
[diagram-design](https://github.com/cathrynlavery/diagram-design) skill (MIT), tested with commit `f24d98b`
(plugin 2.6.141): architecture type, "faithful" detail level (eleven pieces in three zones), the skill's editorial
tokens plus one colour per kind of piece. The figure is generated by a Python script, not drawn by hand, so editing
it means editing the script.

| File | What it is |
|---|---|
| `how-it-works.py` | The source: words (English and Spanish), positions, routes and colours. Edit this. |
| `how-it-works.html`, `how-it-works.es.html` | The page on GitHub Pages ([English](https://jonjunq.github.io/claudia/diagrams/how-it-works.html), [Spanish](https://jonjunq.github.io/claudia/diagrams/how-it-works.es.html)): light or dark following your system, with a short summary. Loads Google Fonts. |
| `how-it-works-light.svg`, `how-it-works-dark.svg` (and `.es.svg`) | The images in the README, one per theme. Self-contained: the fonts are embedded. |
| `embed-fonts.py` | Embeds the fonts an SVG uses, as subsets, so it looks the same inside an `<img>`. |
| `build.sh` | Runs all of the above, plus the skill's checks. |
| `FONTS-LICENSE.txt` | Copyright notices and licence of the embedded fonts. |

## Regenerate

Needs Python 3, the diagram-design skill installed (a copy of its `skills/diagram-design` folder) and network access
to `fonts.googleapis.com`:

```bash
DIAGRAM_DESIGN=~/.claude/skills/diagram-design \
VERIFY_GEOMETRY=<diagram-design checkout>/scripts/verify-geometry.py \
docs/diagrams/build.sh
```

It writes the two pages, runs the skill's `self_check.py` and `verify-geometry.py` on them (the second lives in the
skill's repository, not in the installed skill; without it, that check is skipped), exports one bare page per theme
and language with the skill's `export_svg.py`, and embeds the fonts. Intermediate files go to `build/`, which is not
committed. Look at the result in a browser in both themes before committing.

## Why the fonts are embedded

GitHub shows README images through `<img>`, and a browser draws an SVG loaded that way without fetching anything:
no Google Fonts, so the text would fall back to whatever the system has and lose the look. `embed-fonts.py` reads
which characters each face draws, asks the Google Fonts API for a subset with exactly those characters (`&text=`)
and writes it into the SVG as `@font-face` rules with `data:` URIs. Each SVG ends up around 50 KB. If you change a
word, rebuild: a character that is not in the subset falls back to a system face.
